# 外链助手 · Linkflow

个人外链计划桌面客户端：输入网站域名和联系邮箱，匹配合适的免费渠道、安排月度任务、保存账号与核验公开链接。默认每个网站每月 2 个来源，可调整、暂停。

## 下载与使用

首次安装时，在本仓库 Releases 下载与你的电脑对应的版本：Windows x64 安装程序或 macOS 14 或更新系统的 Apple Silicon ZIP。仅使用本仓库发布的文件，并核对随包 SHA-256。

Mac 解压后，请将“外链助手.app”放进“应用程序”文件夹（也支持当前用户的“应用程序”文件夹），再打开使用。更新中心需要能够确认并写入这个安装位置。

未经 Apple 公证的 Mac 版本可能要求用户确认来源。默认 Mac 打包流程要求 Developer ID 签名和 Apple 公证；发布者明确选择未公证分发时，发行说明必须披露这一状态，并验证 ad-hoc 完整性、版本、架构和更新清单签名。流程代码完成不代表安装包已通过公证，具体以对应版本的发行验收为准。本项目不要求关闭系统安全保护。Windows 目前没有商业代码签名；未提供 Intel Mac 版本。

### macOS Apple Silicon 命令行安装

1.2.7 发行附带一个只安装该正式版本的命令行安装器。先下载并阅读脚本，再单独执行；不要使用 `curl | sh`：

```sh
installer_path="$(/usr/bin/mktemp -t linkflow-install)"
/usr/bin/curl --fail --location --proto '=https' --proto-redir '=https' --tlsv1.2 \
  --output "$installer_path" \
  https://github.com/xiaogan123/linkflow-desktop/releases/download/v1.2.7/install-mac.sh
/usr/bin/less "$installer_path"
/bin/bash "$installer_path"
```

发行时会把确切版本和对应 ZIP 的 SHA-256 写入该脚本。安装器只从本项目的官方 GitHub Release 下载这一个包，先核对摘要，再检查 ZIP 路径与内部符号链接、固定的 Bundle ID 与版本、Apple Silicon 架构及严格 ad-hoc 签名。它以 `ditto --noqtn` 解包，并要求解包树的来源隔离属性为零；安装器不包含主动删除扩展属性的路径，发现异常就在写入安装目录前终止。校验全部通过后，它原子替换 `/Applications/外链助手.app`，并保留旧应用回滚副本。它不读写用户数据，不会结束运行中的进程；检测到应用正在运行时，请先正常退出再重试。没有 `/Applications` 写入权限时，脚本会明确退出，不安装常驻或提权助手。

命令行安装器只使用 macOS 14 自带的系统命令，不依赖 Python、Node.js 或第三方包。缺少所需系统命令时它会报错停止，不会自动安装依赖。

通过浏览器直接下载未公证 ZIP 后手动安装，macOS 仍可能要求亲自确认来源。命令行安装器也不承诺 `spctl --assess` 显示已接受；没有 Developer ID 和 Apple 公证的版本不应声称已获得这种系统信任。已发布的原始 1.2.5 Mac 版本的应用内更新辅助流程会主动写入来源隔离属性；从 1.2.5 或 1.2.6 升级到 1.2.7 时，请使用上述命令行安装器完成一次迁移。

1. 打开设置，选择已登录的本机 Codex CLI，或填写自己的 HTTPS API 服务和 Key，从服务返回的模型列表选择模型并测试连接；自定义模型仍可填写。
2. 添加公开网站域名、联系邮箱与每月目标，并选择“AI 核对后自动发布”或“人工审核后发布”；之后可在编辑网站中修改。
3. 如需自动收取验证邮件，在邮箱池添加一个或多个本人的收件箱，配置 IMAP TLS 和应用密码，并绑定网站与账号。只有联系邮箱地址不会赋予收信权限。
4. 软件运行且电脑联网时推进任务；验证码、手机验证、平台协议或变化的页面可能需要你接续处理。
5. 自动模式下，生成稿件后会另行调用 AI 核对公开证据与渠道规则；通过后继续发布；临时服务失败有限重试，渠道或证据不足时保留记录并继续其他可执行来源；需要登录、验证或人工审核时集中提示。每个网站可分别选择模式；全局设置只影响新站默认值和未单独设定模式的旧站。切换模式会重新核对未发布稿件，不恢复已暂停的计划。

关闭主窗口后可留在菜单栏/托盘运行；完全退出或休眠期间不会执行。首次保存密码时，系统可能需要你授权使用本机加密服务。

## 功能与实际范围

- 本地 SQLite 保存网站、任务与记录，密码和连接凭据使用操作系统加密能力保存；不内置任何用户账号或模型 Key。
- 按自然月创建计划；待审核任务预留名额；避免同来源重复提交和中断后的不确定重复投稿。
- 内置 67 个候选渠道（60 条启用、7 条停用参考）：4 个本人资料类渠道接入受限浏览器流程，Telegraph 与 GitHub Gist 接入官方 API，其余提供资料和人工入口，或因规则限制停用。候选库不是完整互联网目录。列表可按网站类别、费用、注册/邮箱/文章要求筛选，展开查看条件和官方规则。
- 自动能力按具体渠道显示；各第三方平台的真实注册/发布流程尚未全部实测。当前四个资料页渠道首次账号均须由本人创建后导入；GitHub 要求真人注册，其余平台的自动注册尚未完成验收。人工渠道可建立待办、由 AI 准备允许的材料、继续已有任务；尚未接入该平台的自动填写与最终提交。页面变化、平台限制或编辑器不兼容会暂停并提示处理。
- 提交不等于生效。匿名获取公开结果页面并找到指向目标域名的链接后才计数；不承诺搜索收录、排名或 SEO 收益。
- 只计划免费刊登渠道；AI 服务仍可能消耗你的订阅额度或 API 费用。没有可靠第三方数据时，权重与流量显示未知。
- 支持加密备份与 CSV 导出。备份含连接凭据，需要独立口令，请保存在私人位置。
- 只维护你有权管理的网站和本人账号；尊重平台规则，不自动绕过验证码或付费限制。

1.2.0 起，后续更新可在侧栏“更新中心”内检查、下载，再选择“安装并重启”。更新前需等待当前任务结束；下载可取消。更新不会迁移或删除本机网站、账号和设置。网络无法访问 GitHub 时会明确报错，可以稍后重试。

更新清单使用应用内固定公钥验签，安装包核对 SHA-256 与大小。Mac 仍接受系统来源检查，系统要求确认时需用户自行处理；发布者签名不代表 Apple 公证。旧版会保留到新版本确认启动。

## 构建与测试

使用 Node.js 24 与 npm：

```sh
npm ci
npm test
npm run build
npm run test:desktop
npm run test:integration
npm run test:update-ui
npm run test:site-review-ui
npm run package:mac  # 在 Apple Silicon Mac 上
npm run package:win # 在 Windows x64 上
npm run test:packaged
```

正式 Mac 构建须在本机钥匙串中配置有效的 Developer ID Application 证书及 `notarytool` 凭据配置，并通过环境变量 `LINKFLOW_MAC_SIGNING_IDENTITY`、`LINKFLOW_MAC_NOTARY_PROFILE` 指定名称。不要在命令行、日志或仓库中填写私钥或 Apple 账号密码。打包会依次完成签名、公证、附票及系统验证；任何一步失败都不产出正式发行包。更新清单签名入口会重新解包检查精确 Mac 制品。

仅做本地调试时，先构建，再运行 `node scripts/package.mjs mac-arm64 --local`；输出带 `local-adhoc` 标记，不可作为正式更新发布。当前云端 Mac 工作流没有配置 Apple 凭据，应在本机完成构建。经发布者明确授权的未公证分发使用 `node scripts/package.mjs mac-arm64 --unnotarized-release`，再以 `node scripts/sign-update.mjs <说明文件> --allow-unnotarized-mac` 签清单；说明必须包含“Mac 未经过 Apple 公证”。打包流程会对最终应用整体重做 ad-hoc 签名，从最终 ZIP 重新解包后严格验签并确认不带来源隔离属性。浏览器下载仍可能重新加上该属性，用户可能仍需亲自确认来源。此模式不代表 Apple 公证通过。

公开 Actions 工作流仅手动触发，使用标准 GitHub 托管 runner。构建产物通过测试和隐私检查后才会发到 Releases。Mac 与 Windows 分别在原生系统运行；不将跨平台打包等同于原生验证。

源码仓库和安装包不包含本机数据、开发会话、私人审计报告或用户配置。产品运行必需的 AI 指令属于公开实现，用户的 API Key、邮箱授权码和平台密码不会作为这些指令传给模型。

### 1.0.2 使用改进

- 账号在自动任务中注册并加密保存，下次复用已有身份（1.1 起支持明确的网站与账号绑定）；导入已有账号为可选入口。账号错误会分类处理，只有明确未创建的草稿可有限修复用户名冲突，不绕过封禁或风控重新开号。
- 邮箱默认 Gmail，支持 QQ、163、126、Yahoo、iCloud 常用 IMAP 预设；仍需本人提供应用专用密码或授权码。Outlook OAuth 登录尚未接入。
- 更换邮箱服务器或账号会清除旧连接密码；“保存并测试”检验当前填写的配置。

### 1.0.3 完整流程与监控

- 增加真实资格判断：内容或 AI 主题本身不代表拥有软件、代码项目、艺术作品或本地商家资格。缺少适合渠道会显示差额，不通过错误分类或重复发文凑数。
- Telegraph 可通过官方 API 创建作者、加密保存访问令牌、生成原创文章并发布。中文网址、引用与代码块受支持；注册/提交不确定时保留断点，避免重复创建。金融相关内容先在客户端核对后发布。
- 公开页面核验区分“找到链接”“页面中未发现”“暂时无法访问”和“地址无效”，网络错误不会直接当作链接消失。
- Bing 使用用户提供的 Webmaster API Key，每天读取一次首页来源报告。GSC 官方 API 不提供外链报告，因此使用控制台来源网页 CSV 快照导入；这些报告不等于索引或排名保证。
- 当系统 DNS 全部返回代理 fake-IP 网段时，使用固定 Cloudflare HTTPS DNS 查询真实公网地址，再固定地址连接。仍拒绝私有地址、混合答案及不安全跳转；该 DNS 服务会收到待查询的域名。

连接邮箱仍需你提供应用专用密码；Telegraph 作者令牌流程不依赖邮箱验证。文章发布与搜索报告受第三方服务可用性影响。

### 1.0.4 GitHub Gist 接入

- 账号页连接一次已有 GitHub 身份的 Gist 访问令牌（classic `gist` 或 fine-grained Gists 读写权限），令牌仅在本机加密保存，可更新并跨网站复用。不自动创建 GitHub 账号或规避平台限制。
- Gist 仅匹配本人维护的真实技术项目；准备可复用模板、代码或技术说明，核对草稿后通过官方 API 发布。不能以广告为主要内容。
- 网站详情支持接回外部已经发布的公开 Gist：匿名确认公开性、发布时间和正文目标链接，再按原发布时间统计。重复接回不重复计数；普通填写地址也执行相同检查。
- 已提交但返回超时、5xx 等不确定结果时保留断点，不重复发文。公开 API 响应不等于外链成功，还要通过匿名 HTML 核验；搜索引擎收录仍单独确认。
- 新发布接口通过隔离响应和桌面集成回归；没有有效 Gist 令牌时不声称已完成真实 API 发布。


### 1.1.0 工作台与长期维护

- 总览区分本月首次核验、当前可确认有效、需处理任务和剩余合适渠道；任务中心集中查看跨站任务、稿件、公开结果与核验记录。
- 账号按列表展示，支持同渠道多个身份、明确绑定网站与收件箱；历史任务保留使用过的账号。单链接资料页限制跨站共用，避免覆盖已有网站地址。
- 支持多个 Gist 身份和多个验证邮箱，邮箱可逐个添加或从本地 JSON 导入。凭据不进入界面快照；不会为了绕过平台限制重复注册账号。
- 模型从当前服务发现并选择，Codex 无可用列表时明确说明；不会在指定模型不可用时悄悄改用其他模型。支持选择服务支持的推理等级。
- 内置渠道扩展到 50 个，新增 10 个为人工候选；软件、代码包、插件、扩展等分别核对资格。支持自行添加人工渠道，以及导入带来源、日期、统计口径的权重和流量；未取得数据就显示未知。
- 链接消失后保留首次获得记录，安排后续复查；审核超时与已存在过的链接丢失分别显示。网站当前存活和本月新增不混为一个数字。
- 普通网页与公开结果可用系统默认浏览器、Chrome 或 Edge 打开，操作系统和浏览器决定复用哪个窗口；自动任务仍使用隔离的执行窗口，不复制日常浏览器会话。
- 顶部连续区域支持拖动窗口；更紧凑的列表、筛选和侧边表单减少大段空白与反复滚动。
- 本机自动加密备份默认关闭，开启后在应用运行时每 24 小时保存，默认保留最近 7 份；只能在原电脑和原系统账号下恢复。跨机迁移请使用独立口令的加密备份。恢复后暂停自动执行。
- 设置中可手动检查本仓库的最新稳定版本并打开下载页，不自动下载或安装更新。

发布检查覆盖当前源码与 Git 历史、构建目录、应用包内外、安装包解压内容和公开下载文件。私有匹配词和详细审计证据仅保留在私人位置；公开 CI 使用通用扫描，不能代替最终安装包的独立隐私复核。

### 1.2.0 应用内更新中心

- 独立查看当前版本、可用版本、发布说明与下载进度；下载失败可取消或重试。
- 用户主动安装后由独立助手等待旧进程退出，原地更新并重启；未完成启动确认时保留恢复路径。
- 不接受界面传入任意下载地址、安装位置或执行参数；仅安装本仓库签名清单授权的包，不自动降级。
- 发布者在两平台原生验证和隐私检查后，使用保存在仓库外的 Ed25519 私钥运行 `npm run update:sign -- <发布说明文件>`。环境变量 `LINKFLOW_UPDATE_SIGNING_KEY` 只提供私钥文件路径；私钥不得放进源码、CI、安装包或发布附件。
- 每次发行须同时上传对应安装包、`linkflow-update.json` 与 `linkflow-update.json.sig`；签名针对清单原始字节，上传后不得重新格式化。
- 可按平台分别发行：默认签名命令要求两个平台齐全；明确追加 `--platform windows-x64` 时只提供 Windows 更新。未提供安装包的平台保留当前版本，更新中心会提示暂未提供该平台安装包。默认的 Mac 签名入口仍须通过真实签名和公证检查；明确选择 `--allow-unnotarized-mac` 时仅接受完整性有效、身份/版本/架构匹配且说明已披露的 ad-hoc 包。

### 1.2.1：独立审核与渠道适配

本次发行范围为 Windows x64。macOS 1.2.1 保留为候选，等待 Developer ID 签名、Apple 公证及正常首次启动验收。

- 新网站分析后按当前可用条件建立任务；总览分别显示暂停、排队、审核、需处理和渠道缺额，实际执行时间与自然月边界分开。
- 客户端自动发布的文章都经过审核。开启 AI 模式后，生成与审核是两个独立调用；审核核对实际抓取证据中的引用。改稿、相关配置变化或恢复备份后，不沿用失效的通过记录。人工渠道在平台上的外部操作仍需用户核对。
- 新增 8 条渠道记录，金融与加密内容可快速筛选，并查看未匹配的具体原因。其中 6 条是有条件的人工候选，2 条因当前规则限制停用；没有增加自动发布接口。原创内容、真实身份及平台资格仍须分别满足。
- 渠道的规则日期、费用和执行方式明确显示；没有可靠来源的权重和流量继续显示未知。新候选数量不代表已获得外链，也不保证适合所有返佣网站。

### 1.2.2：审计修复与人工渠道工作流

1.2.2 首次发行仅提供 Windows x64；随后经发布者明确授权追加未公证的 Apple Silicon Mac 分发，具体状态与限制以本版本发行说明为准。

- 渠道库从 58 条扩为 67 条，新增 7 条有条件的人工候选与 2 条停用参考。补齐平台资格、推广和 AI 内容条件；未新增自动发布接口。
- 渠道详情可选择网站、建立人工待办或继续该来源的已有任务；任务中心可准备投稿材料。剩余容量按来源域名去重。
- 托管出版物的公开地址采用明确的来源子域规则，接回任务与公开核验使用一致的判断。

- 修正验证邮件轮询截止时间、设置与加密凭据的原子保存、Windows 外部浏览器打开后持续等待退出的问题。
- 四个资料页渠道首次账号由本人创建后导入，已有本人账号的登录和资料维护保留；注册拦截覆盖账号创建与浏览器导航。
- 登录启动设置先回读系统实际状态；系统拒绝或本地保存失败时明确报错并尝试恢复，避免显示虚假的已开启状态。

### 1.2.2 Mac 发行补充

本次经发布者明确授权增加 Apple Silicon Mac 更新。Mac 未经过 Apple 公证，首次打开或更新后可能需要用户在系统设置中亲自确认来源；更新清单仍使用固定公钥验签，并核对安装包摘要和大小。最低系统声明为 macOS 14.0，当前原生测试平台以对应发行验收为准；不提供 Intel Mac 包。Windows 安装包复用已验收的 1.2.2 制品。未公证更新如被系统拦截，应用会保留恢复副本；延迟确认后当前更新中心可能仍显示未完成，请保留文件并联系支持处理，不要反复点击安装。

### 1.2.3：按站审核与渠道发现

- 添加、编辑网站时可分别选择 AI 核对后自动发布或人工审核；生成与核对仍是独立步骤。切换模式保留稿件、清除旧授权，未提交稿件重新核对；升级不会擅自改变已有网站的发布权限。
- 渠道推荐区分推荐尝试、可尝试、准备条件和暂不适用。相关主题、可翻译语言和公开页面可识别的工具形态用于推荐；添加网站无需填写资格证明表单。
- 普通品牌资料、博客和有条件的软件目录可先准备材料，实际提交仍核对具体平台条件。真实软件包、插件、开源项目和本地商家资格不能凭空生成；候选增加不等于新增自动发布接口。
- 尚未接通的渠道继续使用人工材料准备流程，不自动提交。已接通渠道仍按账号、内容和平台条件执行。
- 更新中心在当前平台没有安装包时也可重新检查，后续补发对应包后无需退出应用。
- 同时提供 Windows x64 与 Apple Silicon Mac 更新。Mac 未经过 Apple 公证；来源确认、延迟确认后的恢复状态和最低系统实机覆盖限制仍适用。


## 1.2.5 自动优先与账号入口

- 添加网站后，优先安排已连接账号、无需账号和可由官方 API 准备身份的渠道。缺少第三方账号不会挡住其他可执行来源；首次登录、验证码和人工提交仍需本人处理。
- Telegraph 身份由任务通过官方 API 自动准备，不需在导入窗口填写邮箱或密码。GitHub Gist 使用单独的令牌连接入口；已有 API 身份只在账号列表中修改绑定。
- 临时证据读取或 AI 服务失败使用有限重试；每日额度耗尽后等待下一个本地自然日。无法核实的渠道保留记录，不重复付费核对同一稿件，也不重复投稿凑月度数量。
- 自动任务与需要本人操作的任务分别显示。没有剩余可执行渠道时如实显示等待条件，不承诺达到固定外链数量。
- 更新中心将上次失败更新的版本与最新版本分开显示，并显示恢复验证阶段和脱敏失败类别。这项诊断改进不代表所有旧 Mac 更新恢复故障已经解决；原事务与恢复副本继续保留。
